# 文章排版检查与修复

## 日常使用

```bash
pnpm posts:lint
pnpm posts:format
pnpm posts:lint "posts/HUSTNLP NAS 使用说明.md"
pnpm posts:format "posts/HUSTNLP NAS 使用说明.md"
pnpm posts:test
```

默认递归处理 `posts/` 下的 `.md` 和 `.mdx`，也可以传一个或多个文件/目录。
检查和修复完全离线，不需要 GitHub Token，不暂存、不提交、不推送，也不更新 Discussion。
请在修复后审阅 `git diff`。

`posts:lint` 发现待修复内容时返回非零退出码，报告文件、行列、规则与替换建议。
`posts:format` 先完成所有目标文件的解析、保护性校验和幂等性校验，再写入；
任何解析错误、补丁冲突、锚点冲突或保护校验失败，整批不写入并返回非零退出码。
检查期间文件被其他程序修改也会中止。它不是磁盘事务；写入阶段发生 I/O 错误时会尝试回滚已写入的文件。

## 修改类别

| 区域 | 自动处理 | 保留内容 |
| --- | --- | --- |
| 正文、标题、列表、表格 | 中英文及数字间距、全角字母数字转半角、中文语境标点 | 原有换行、缩进、表格分隔线 |
| 强调、删除线、行内代码外侧 | 可见文案和跨节点间距，如 `中文**English**中文` | 强调分隔符、行内代码内容 |
| 引用、五种 Alert | 同一套文案规则 | `>`、`[!NOTE]` 等标记 |
| 链接、图片 | 链接可见文字、人工撰写的图片描述 | URL、邮箱、图片文件名、自动截图标识 |
| Front Matter | 仅 `title`、`summary` 字符串 | 引号、多行样式、其他字段；不补写缺失摘要 |
| MDX | 子文本、`Details.summary`、HTML 小写标签的 `title` / `alt` / `aria-label` 静态属性 | 标签、其他属性、JS 表达式、import/export、script/style/pre/code 内容 |
| HTML / MDX 注释 | 普通自然语言说明 | 来源标记、工具指令 |
| 已知语言代码块 | Shiki 识别出的自然语言注释 | 字符串、变量、命令、缩进、围栏、文件名与元信息 |
| 公式 | 不修改 | `$…$`、`$$…$$`、`\(…\)`、`\[…\]` 的完整内容 |
| 文件名 | 仅提示建议 | 不自动改名，避免破坏 Discussion 来源路径 |

中文语境使用 `，。；：！？（）“”‘’`，英文段落保留半角标点。
小数、版本号、文件扩展名、标题编号中的点和含义不明确的 ASCII 点不强行替换。
不自动纠正拼写、产品名大小写、措辞，不使用 LLM。

### 技术表达与混合语言的边界

- 函数调用（如 `x.wait()`、`P(mutex)`，包括嵌套调用）和 ASCII 有序对（如 `(i, j)`）保留半角括号、逗号及内部空格，不按中文标点转换。
- 在文章中仍建议用行内代码标记函数、变量和路径；复杂数学表达式使用公式定界符。自动识别不是编程语言或数学语法的完整解析器，有歧义时需明确标记。
- 中文路径可能与后续中文说明连在一起，工具不会猜测路径终点。例如注释应写作 ``# 占用 `./hdc/` 的进程``，而不是 `# 占用./hdc/的进程`；反引号内的中文路径也保持原样。
- 英文注释附带中文括号说明时，分别处理两个区域：英文部分保留半角标点，只格式化中文说明。其他难以区分语境的中英文长段落建议分行书写。
- `\{`、`\}` 等转义标点不会被当作英文单词添加空格；装饰性分割注释（如 `#####分割线#####`、`/* =====说明===== */`）整体保留。

规则不会猜测已全角化的符号原本是不是代码。历史误改需要人工恢复一次；使用行内代码明确边界后，重复格式化不会再改变它们。

## 代码注释的安全边界

```bash
echo "${HOME}" #中文English注释
```

修复为：

```bash
echo "${HOME}" # 中文 English 注释
```

使用 Shiki 的 TextMate scope 与细分 explanation 识别注释，不根据语法高亮颜色猜测。
字符串或 heredoc 内的 `#` / `//` 不是可修改注释。JSON 示例使用 JSONC 语法识别注释；
Makefile 的 Tab 保留，recipe 使用 Bash 分词识别注释。

以下内容受到额外保护：

- shebang、编码声明、Shiki/Twoslash、lint、type-ignore、编译器指令。
- `@param` 的标签、类型、参数名；仅修改其说明。未知 `@` 指令不修改。
- 注释中的反引号、路径、URL、变量、引号包裹的字面值。
- 装饰性分割线，以及英文注释中的英文标点（中文括号说明单独处理）。
- 可识别的被注释代码，以及 `# 或：clashsub ...` 这类带参数的备用命令。

无语言、`text` / `txt` / `plaintext` 或未知语言代码块原样保留，输出 `code-coverage` 提示。
这些提示和文件名建议属于覆盖范围说明，不作为排版违规阻止发布。
需要处理这些代码块的注释时，应先补充准确的语言名；输出日志、ASCII 图和纯文本不要冒充代码语言。
语法高亮器不是编译器；有歧义的技术文本优先保留，必要时用反引号明确保护边界。

## 章节链接兼容

标题排版改变 GitHub 风格 slug 时，在标题之前加入独立旧锚点：

```markdown
<a id="安装linux"></a>

## 安装 Linux
```

重复标题使用递增后缀。已有旧锚点保留，不重复插入；新旧 ID 冲突时中止修复并提示人工处理。
本次处理范围内的同页链接、相对 Markdown 文件链接、`m0rtzz.com` / `www.m0rtzz.com` 的
`/posts/编号#章节` 链接会更新到新锚点，第三方 URL 不改。
建议批量运行以更新所有文章间的链接；只指定个别文件时，范围外链接仍可通过旧锚点访问。
请勿随意删除生成的旧锚点，否则已收藏或外部引用的章节链接会失效。

## 发布门禁与实现

`posts:check` 先进行本地排版检查，再验证 Front Matter 和远端 Discussion。
因此现有 pre-push、prebuild、GitHub Actions 都会检查排版；
`posts:sync` 和 `posts:sync:dry-run` 也在访问远端之前检查。
CI 另运行 `posts:test`，验证公式、代码、注释、MDX、锚点、批量失败保护和幂等性。

规则入口在 `scripts/typography/text.mjs`，Markdown 处理在 `markdown.mjs`，
注释识别在 `code.mjs`，章节链接更新在 `links.mjs`。
AutoCorrect 仅用于经过白名单提取和技术字面值保护的文本，不对整篇 Markdown 直接运行默认 `--fix`。
修复按源位置应用，不整篇 stringify，因此不会重新排版围栏、表格或 LF/CRLF。
此工具不修改网站的 Markdown 渲染、数学插件顺序、代码复制和高亮逻辑。
